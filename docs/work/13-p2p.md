## 2. Technology Decisions & Layer Separation

```text
P2P Network Implementation  : Go (apps/p2p or designated workspace path)
Core / Ledger / Consensus   : Rust (crates/scytale-*)
Architectural Boundary      : Explicit Language-Agnostic Interface
```

```text
                 SCYTALE VALIDATING NODE
                           │
        ┌──────────────────┴──────────────────┐
        │                                     │
      Go P2P                               Rust Core
        │                                     │
  - TCP Connection Handshake            - Stateless Structural Validation
  - Peer Discovery & Session Table      - UTXO State Mutation
  - Message Framing & Codecs            - Consensus Rule Engine (13 Rules)
  - Inventory Gossip & Duplicate Filter - redb Canonical Storage
        │                                     │
        └────────────── Explicit ─────────────┘
                   IPC / RPC Boundary
```

- **Fundamental Invariant:** *Network transports data; Consensus validates data.* P2P peer assertions are treated as untrusted transport envelopes until verified locally by the Rust consensus engine.

## 3. Scope & Non-Goals

### In Scope:
- Go P2P module initialization and TCP connection lifecycle management.
- Protocol version and Network ID handshake exchange.
- Wire message framing, length delimitation, and decoding.
- Two-step inventory gossip (`Announce ID` $\rightarrow$ `Request Data` $\rightarrow$ `Relay Full Object`).
- Initial Block Synchronization (IBD) locator negotiation and batched block streaming.
- Backpressure flow control and peer misbehavior disconnect policies.
- Unit, multi-peer integration, sync convergence, and network failure test suites.

### Out of Scope / Non-Goals:
- Implementing UTXO mutation, signature verification, or difficulty retargeting inside Go (Rust consensus domain).
- Persisting canonical chain blocks to disk in `redb` (deferred to Task 14 / Storage).
- Designing user-facing Passbook wallet RPC endpoints or UI components.

## 4. Work Items

### W1 — Inspect Existing Workspace Structure
- Inspect the repository layout for Go application placement (`apps/` vs. root modules).
- Ensure Go module definitions remain cleanly decoupled from the Rust Cargo workspace.

### W2 — Implement Peer Model & Connection State Machine
- Implement the Go peer connection state machine:
  ```text
  DISCONNECTED ──> CONNECTING ──> CONNECTED ──> HANDSHAKE ──> READY ──> ACTIVE ──> CLOSING ──> DISCONNECTED
                                                                        │
                                      Any Protocol Violation ─────────┴──> FAILED (Disconnect)
  ```

### W3 — Handshake & Network ID Verification
- Exchange initial handshake packet containing:
  `Protocol Version`, `Network Identifier`, `Peer Identity`, `Best Block Hash`, and `Best Height`.
- Instantly disconnect peers presenting mismatched Network IDs or incompatible protocol versions.

### W4 — Message Framing & Decoding Engine
- Implement length-delimited wire framing:
  `[ 4-byte Magic | 12-byte Command | 4-byte Payload Length | 4-byte Checksum | Payload Bytes ]`.
- Reject oversized or malformed frames safely without process panics.

### W5 — Transaction Gossip Engine
- Announce unconfirmed transactions using lightweight 32-byte `TxID` inventory messages.
- Request full transaction payloads only if `TxID` is not present in local mempool or known cache.

### W6 — Block Propagation Engine
- Announce newly discovered canonical blocks via `BlockID` inventory broadcasts.
- Stream full `Block` payloads upon peer request and forward directly to the Rust validation boundary.

### W7 — Initial Block Synchronization (IBD)
- Implement block locator hash negotiation to identify the common ancestor fork point.
- Download missing historical blocks in bounded batches with pipeline backpressure.

### W8 — Explicit Rust ↔ Go IPC/RPC Integration
- Expose the transport boundary interface:
  - **Go $\rightarrow$ Rust:** `SubmitTransaction(raw_bytes)`, `SubmitBlock(raw_bytes)`, `GetBlockLocator()`.
  - **Rust $\rightarrow$ Go:** `BroadcastTransaction(txid)`, `BroadcastBlock(block_bytes)`.

## 6. Error & Misbehavior Model

The Go P2P layer distinguishes between transport framing failures and ledger invalidity:

```text
1. Malformed Wire Message (Framing error, invalid length, checksum mismatch):
   ──> Immediate connection termination & peer IP penalty.

2. Well-Formed Message Containing Invalid Ledger Object (Corrupt tx signature, invalid PoW):
   ──> Forwarded to Rust Core ──> Rejected by Consensus ──> Peer misbehavior score incremented.
```

## 7. Test Strategy & Verification Plan

In accordance with [`docs/TESTING-STRATEGY.md`](../TESTING-STRATEGY.md), implementation of Task 13 must fulfill the following test suites:

### Go Unit Tests:
- `TestPeerConnectionStateTransitions`: Verify state machine transitions from `CONNECTING` to `READY`.
- `TestHandshakeNetworkIdMismatch`: Verify immediate rejection on mismatched network ID.
- `TestMessageFramingCodec`: Verify encoding, decoding, length bounds, and checksum validation.
- `TestDuplicateSuppression`: Assert duplicate `TxID` / `BlockID` announcements are ignored.

### Multi-Node Integration Tests:
- `TestTwoNodeGossipRelay`: Connect Go Peer A and Go Peer B; assert transaction announced on A is received and decoded on B.
- `TestInitialBlockSyncConvergence`: Node A (Height 0) connects to Node B (Height 50); assert Node A downloads all 50 blocks in batches and catches up.
- `TestMalformedPacketRejection`: Inject corrupted byte streams; assert graceful disconnection without daemon crash.

### End-to-End Reality Test:
- Launch two complete Scytale nodes (Go P2P + Rust Core), mine a block on Node 1, propagate via Go P2P, and assert Node 2 consensus engine accepts and commits the block.
